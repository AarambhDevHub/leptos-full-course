# Update to Leptos 0.8.22

## Versions

| Crate | Before | Now |
|-------|--------|-----|
| `leptos` | 0.8.19 | 0.8.22 |
| `leptos_meta` | 0.8.6 | 0.8.7 |
| `leptos_router` | 0.8.13 | 0.8.17 |
| `leptos_axum` | 0.8.9 | 0.8.10 |

Minimum Rust is now documented as 1.89 (Leptos 0.8.22 needs 1.88, and the latest `uuid` needs 1.89). The READMEs previously said 1.78.

No course code needed API changes for 0.8.22.

## Fixes made while verifying

- **Module 10 and 11:** the tables were never created, so a fresh database returned `relation "notes" does not exist` (module 10) or failed on register (module 11). Both now run their idempotent `migrations/0001_init.sql` at startup. They intentionally do not use SQLx's migration tracker, because modules 10, 11 and 25 share one database and all have a migration numbered `0001`.
- **Module 04:** todo ids were made with `items.len() + 1`, so deleting a todo and then adding one reused an id and the new row silently never appeared in the keyed `<For/>` list. Ids now come from a counter that only goes up.
- **Module 08:** the sample todos were re-added whenever the list was empty, so deleting every todo brought them back. They are now seeded only once.
- **Module 09:** with default streaming, the per-article `Meta` description inside `Suspense` never reached the `<head>`, and the home page had two `description` tags. The article route now uses `SsrMode::Async` (title and description are in the first response) and the duplicate app-level description was removed.
- **Module 10:** the note preview sliced the body by bytes (`&body[..50]`), so a long Hindi (or emoji) note panicked and killed the whole WebAssembly app. It now counts characters, with three unit tests. Also: after saving an edit the card kept showing the old title (the keyed row displayed a captured copy), `update_note` accepted a blank title, and the tables are created at startup (see above).
- **Module 11 and 25:** every password was hashed with the same fixed salt, so two users with the same password had identical hashes. Each password now gets a fresh random salt (existing users can still log in, because the salt is stored inside the hash). A duplicate email no longer returns the raw database error (it leaked the constraint name); it returns "that email is already registered" and logs the real error on the server.
- **Module 12:** the cart list showed a stale quantity (a keyed row displayed a captured copy, so "x1" stayed while the summary said 3 items), and notification ids used `len() + 1`, so a new toast could get the id of a live one and never appear. The row now reads its quantity from the cart, and ids come from a counter (`NextNotificationId` newtype in context).
- **Module 13:** the module was titled "Styling and Tailwind" but contains no Tailwind. It is now simply "Styling".
- **Module 14:** a quick second click on the fade toggle let the first timer unmount the box (fixed with a generation number, and the fade now also fades in); two animated-counter loops fought over one signal and the number zigzagged (the newest loop now cancels older ones); the Replay button changed an attribute and restarted nothing (the list is now recreated with a keyed `For`); the bouncing ball's interval used `.forget()` and could never stop (now cleaned up with `on_cleanup`).
- **Module 15:** the module's own tests passed while the code under test had three bugs. Todo ids used `len() + 1` (reused after a delete), `validate_email` accepted `@b.com`, `a@@b.com`, `a@.com`, `a@b.` and addresses with spaces, and `format_file_size` printed `1024.0 KB` for 1,048,575 bytes. Six edge-case tests were written first (they failed), then the helpers were fixed (nine tests pass).
- **Module 16:** the batching demo timed microseconds, so its bars were noise (it now also shows how often an effect runs: once per click either way); the memo-versus-derived call counts never updated after the first render (they now refresh); a typed value above the input's `max` could call `fib(45)` and freeze the tab (the input is clamped, with unit tests); and the "lazy" list created all 200 rows up front (it now renders only the rows revealed so far).
- **Module 17:** uploads over 2 MB (Axum's default limit) were silently dropped while the server answered `ok`. The route now allows 10 MB (matching `.env.example`) and returns real errors (`413` for oversized files).
- **Module 17 (part 7 review):** the browser treated every answer as success (XHR `load` fires for `413` too), so an oversized upload showed a full progress bar and an empty error line; it now reads the status, reports network failures, and refuses files that cannot fit before sending. File names are cleaned by one tested function (path stripped, Hindi names keep their extension instead of collapsing to `.txt`, `..` no longer returns `500`), and two uploads with the same name no longer overwrite each other (`name-2.ext`, written with `create_new`). `format_size` had the `1024.0 KB` boundary bug from module 15 and is fixed. Nine unit tests.
- **Module 18:** the sender saw every message twice (a local copy plus the room's echo); a WebSocket ping or binary frame silently closed the connection; a slow client that fell 64 messages behind stopped receiving without any error; the server relayed anything, including 5 MB texts and invalid JSON; Leave only changed a label and left the socket open, Connect twice made two sockets, reconnects always used the user name "learner" and the retry budget was never reset. The server now validates and size-limits every message, keeps the connection through pings, binary frames and lag, and announces a departure even when the browser just disappears; the client keeps one socket (generation numbers), really closes it on Leave, reconnects with backoff as the real user and resets its budget after a good connection. Eight unit tests.
- **Module 19:** the server sends named events (`clock`, `tick`, `progress`, `notification`) but the page used `onmessage`, which only receives unnamed events, so every panel stayed on "Events: 0"; the progress stream ended after 100 percent and the browser reconnected and restarted it forever (it now ends with a `done` event and the client closes the stream); Connect twice opened two streams and the cleanup was registered inside a click handler, where no owner exists (cleanup now belongs to the component, and there is a Disconnect button). Three unit tests.

## How this was verified

- Type-checked all 25 modules with `cargo check` (CSR, `ssr` and `hydrate`): no errors, no warnings.
- Built all 25 modules to `wasm32-unknown-unknown`.
- Ran the 14 CSR modules in jsdom: all mount and survive clicking every button; modules 01, 05, 06 and 07 have behavior tests (counter, form validation, routing, async resources).
- Ran modules 15 and 16: nine native unit tests (six written first and failing), measured release-build sizes (debug, release, wasm-opt, gzip, brotli), and the memo, batching, untracked-read and lazy-list demos in a simulated browser.
- Ran modules 12, 13 and 14 in a simulated browser: cart, toasts, localStorage, wizard and theme; class and style directives, CSS variables and dark mode; fade, counter (every DOM update recorded), replay and ball.
- Hydrated modules 10 and 11 against PostgreSQL 16 and exercised the notes page (edit, optimistic delete, non-English text) and the register, login, logout and admin flows.
- Hydrated the server-rendered modules 08 and 09 in a simulated browser and exercised real server functions, client-side navigation and head tags.
- Ran the 11 server modules and exercised their pages and endpoints, against PostgreSQL 16 for modules 10, 11 and 25.
- `cargo test -p module-15-testing` (3 tests) passes.

Not covered: real-browser rendering and CSS, the `wasm_bindgen_test` tests in module 15 (they need a browser), and `cargo leptos` / `trunk` builds (the checks used `cargo` and `wasm-bindgen` directly).
- **Module 20 (part 8 review):** the `Cache-Control: public, max-age=60` header was set from a POST server function, which browsers never cache, and because the same function also runs during server rendering the header landed on the whole HTML page (a shared cache could keep it). The cached headline is now a GET server function (`endpoint = "cached_headline"`), the header is set only for `/api/` calls, and the manual stale-while-revalidate panel uses a separate `fresh_headline`. `list_items` trusted the client: one request with a huge page size built a 100 MB answer in 5 seconds, and a huge page number overflowed and panicked (silently wrapping in release); `page_window` now validates both (size 1 to 50, page 1 to 1000). Load more waits for the page in flight and offers a retry after an error; polling stops on cleanup, skips hidden tabs and backs off after failures. Static files in `/pkg` now get gzip, `304` answers and an explicit `Cache-Control: must-revalidate` (before: no cache header, no conditional requests). Five unit tests.
- **Module 21:** `dir` had `ltr` on both branches and there was no right-to-left language, so RTL was never shown; Arabic is added with `dir` from the language. The page `lang` stayed `en` while content switched (screen readers used the wrong voice) and the title never changed; both now follow the language. The language buttons had no `aria-pressed` or `lang`; the checkout button repeated its visible text in `aria-label`; the live region always held its message, so it announced "settings saved" on every language change (now it announces only after a Save). The "keyboard-friendly" menu removed items from the tab order but had no arrow keys, so only the first item was reachable; arrows, Home and End now move focus (reversed in RTL). Translation tables are static instead of rebuilt on every lookup, a Spanish accent is fixed, a test checks that every language has every key, the starting language comes from storage or the browser, and a visible focus style was added. Ten unit tests.

Part 7 review (modules 17 to 19): servers built and run natively; upload, WebSocket and SSE endpoints exercised with curl, a Node WebSocket client and a real headless Chromium (browser APIs probed against the real servers); browser-side code type-checked and linted with `hydrate`. The wasm32 target could not be installed in the review environment, so the compiled WebAssembly bundle of these three modules was not clicked through; run `cargo leptos watch` once per module before publishing.
- **Module 22 (part 9 review):** the clipboard button built a script string for `eval`; a line break in the text made a syntax error, and `eval` returned success even when the browser rejected the copy or `navigator.clipboard` did not exist (insecure page), so the panel said "Copy requested" for a copy that never happened. It now uses the asynchronous clipboard API and shows the real result. `use_intersection` never observed anything (the panel waited for ever and a fake button said "Visible"); it is now a real `IntersectionObserver`, disconnected on cleanup. The `localStorage` panel always said "Saved", even when storage was full or blocked; every call now reports its result. The event listener was leaked with `forget` (a second mount doubled the count); the component now owns it. The chart status ignored script errors, and the chart is destroyed with the panel. Chart.js is pinned to 4.4.7. Three unit tests.
- **Module 23 (part 9 review):** the server binary did not compile on Rust 1.97 ("queries overflow the depth limit"); `#![recursion_limit = "512"]` fixes it. The public `log_client_error` wrote any text into the log: a line break forged a fake log line, a two megabyte report was written in full, and 200 requests wrote 200 lines. Text is now cleaned and cut at 500 characters, 30 reports per minute are accepted, and a 64 KB body limit rejects large requests (the limit layer must come after the routes). `unstable_data` echoed any `kind` back; only known kinds are accepted. A failed optimistic delete returned to the wrong place when another item had been deleted meanwhile; it now returns by original order. The button said "Retry with backoff" but did no backoff; it is now "Retry". The delete message is a live region, and the root crash report is sent from an effect. Five unit tests.
- **Module 24 (part 9 review):** the module was not using islands: the whole app was hydrated and the page said otherwise, and the "Hydration cost" table (92 KB, 18 KB, 6 KB) was typed into the source and never measured. It now uses the `islands` feature with three real `#[island]` components (the server HTML contains exactly three `leptos-island` elements) and an honest notes table. The search island used a client-only resource, so the server HTML showed only "Preparing search island..."; the list is now in the server HTML, with a status line. The theme island started as light and overwrote the saved choice, and in dark mode text had a contrast of 1.02 to 1 on the cards; the theme is now applied by a head script before paint, with CSS variables (lowest contrast 8.1 to 1 in both themes) and `aria-pressed`. The newsletter function accepted `@` and a one megabyte address; it now validates the shape and length, and the form has a real label and a status region. Five unit tests.

Part 8 review (modules 20 and 21): module 20 server run natively and probed with curl and real headless Chrome (headers, GET caching, limits, 304 and gzip); module 21 components rendered to HTML natively from the real source (before and after) and its logic unit tested; browser-side code type-checked and linted. Again the compiled WebAssembly was not clicked through, and the arrow key focus movement, the language persistence and the live region announcement need a real browser run with `trunk serve` (module 21) and `cargo leptos watch` (module 20), ideally with a screen reader once.

Part 9 review (modules 22 to 24): modules 23 and 24 servers run natively and probed with curl and real headless Chrome (log injection, size and rate limits, island markup, theme script, contrast, page without JavaScript); the browser-side Rust of all three was type checked and linted, and pure functions unit tested. The compiled WebAssembly was again not built or clicked through: the clipboard, IntersectionObserver, event listener cleanup, island hydration, theme toggle and the new crash report effect need a real run (`trunk serve` in module 22, `cargo leptos watch` in modules 23 and 24).
- **Module 25 (part 10 review):** the JWT secret had a default that was printed in the source, and the compose file used a different public one, so anyone who read the repository could forge a login for any user (confirmed: a token signed with the default was accepted). The server now refuses to start unless `JWT_SECRET` is set, at least 32 characters and not an example value. Login took 460 ms for a known email and 2 ms for an unknown one, which reveals which emails are registered; an unknown email now verifies against a dummy hash (357 ms against 445 ms in a run of five each), the slow hashing moved to the blocking thread pool, and five failed attempts per email in fifteen minutes stop further guesses (in memory, per process). The session cookie now has `Secure` (turn off with `COOKIE_SECURE=false` for plain-http development). Registration accepted the email `@` and a 200 KB password; a one megabyte note title was stored; a NUL character returned a raw database error to the browser. All input is now validated by tested functions in `guard.rs`, request bodies are limited to 64 KB (placed after the routes), and database errors are logged on the server and replaced by one generic message. Deleting a note that was missing or belonged to someone else answered success, and the page ignored the result; it now answers "note not found" and the page shows failures. The activity feed was three typed-in fake events and the dashboard numbers were typed text; both now read the database (every register, login, failed login, logout, note create and delete is recorded) and the dashboard shows counts. A protected page showed "Login required" in the server HTML even for a signed-in user, because the session was copied into a signal by an effect, which does not run on the server; the session is now a resource read inside Suspense. `ProdUser` could be serialised and printed with the password hash and is now server only. Responses carry `nosniff`, `X-Frame-Options`, `Referrer-Policy` and `Permissions-Policy` headers. The Docker image ran the bare binary without the `LEPTOS_*` variables, so the page asked the browser for `/pkg/.js` (confirmed by running the binary from an empty folder); it now sets them, runs as a non-root user and has a health check. The compose file no longer publishes PostgreSQL's port, no longer hard-codes passwords or the secret, and waits for a healthy database. Logging defaults to `info`, the database retry no longer sleeps after the last attempt, the forms have labels, autocomplete and limits, and the README no longer claims uploads and server-sent events. Nine unit tests.

Part 10 review (module 25): server built and run natively against PostgreSQL 16 and probed with curl (forged token, timing, lockout, limits, ownership, activity, headers, server-rendered HTML, SIGTERM shutdown); browser-side Rust type-checked and linted with `hydrate`; pure functions unit tested. Not done: the WebAssembly was not built or clicked through, and the Docker image was NOT built (no Docker daemon was available), so the Dockerfile and compose changes are reviewed by reading and by running the binary the way the container would, not by building them. Not added, on purpose: email confirmation, password reset, a CSRF token (the cookie is `SameSite=Lax`), token revocation, a Content-Security-Policy, and a rate limiter shared between servers; the README lists them.
